## 二、已实现的功能
1. 抓取 UE5 编辑器**活动 3D 视口**的画面
2. 计算并显示 **R / G / B / 亮度** 直方图曲线（对数归一化）
3. 显示统计：平均/最暗/最亮亮度、阴影/中间调/高光占比、平均 R/G/B
4. 手动「捕获视口」按钮 + 「自动刷新（0.5 秒）」开关
5. 底部「直方图诊断」区块，自动判断并提示：
   - 曝光（不足/偏暗/正常/偏亮/过度）
   - 影调比例（暗调/高调/对比生硬/均衡）
   - 对比度（偏低/合适/过高）
   - 色调偏移（偏红/偏蓝/偏黄/偏品红等）及调色建议
6. 「显示」切换按钮，点击循环切换三种直方图模式：
   - **综合**：R / G / B / 亮度 四条曲线叠加
   - **RGB 独立**：R、G、B 各占一行、各自归一化（避免曲线互相压扁），每行带颜色标签
   - **亮度**：只看明暗（Luma）
7. 「黑白预览」开关：在视口对应的世界里生成临时 `PostProcessVolume`（饱和度=0），
   一键把画面转成黑白查看明暗；再点一次、或关闭面板，自动还原（不保存进关卡）
8. 直方图横轴两端标注：**左端「暗」、右端「亮」**，三种显示模式都显示

10. **「伪彩色预览（曝光）」开关 —— 2026-09-18 重做（纯 CPU 版），已编译通过**
    - 做法：抓图后在 CPU 上按 IRE 档位给像素上色，显示在面板里（缩略图 + 图例）。
      `CaptureActiveViewport(Data, OutPixels)` 只在开启时才多输出一份像素，平时零开销。
    - 档位（**2026-09-18 二次修订**，对齐 RED 官方「只在关键档着色、其余显示去饱和灰度」）：
      紫(0-4)=死黑 → 蓝(4-10) → 青(10-12.5)=深阴影 → 灰度(12.5-41) → **绿(41-48)=18% 中灰基准**
      → 灰度(48-61) → **粉(61-70)=肤色** → 灰度(70-92) → 麦秆(92-93.5) → 黄(93.5-95.5)
      → 橙(95.5-98.5) → **红(98.5+)=削波**；其余档由 `bDesaturateOthers=true` 显示灰度。
    - 修订原因（实测数据）：原先把 IRE 10–38 整整 28 个 IRE 单位涂成同一块扁平暗青，
      而实测**视口有 39.6% 的像素都落在这一段**（那块"看着很亮的墙"就在里面）→
      满屏暗青、用户反馈"亮面为什么是黑的"。真机上青只标 10–12，其余走灰度。
      交叉验证方法：直接统计整屏截图里视口区域与面板伪彩图的亮度分档，两者对上 → 数值域没问题，
      是档位表设计问题（**不是 gamma/线性域错误**）。
    - 三个关键设计：
      1) **不生成后期材质** → 从根上避开上次那个 shader 编译失败的坑；
      2) 只给"显示副本"上色，直方图统计仍用原始像素 → **不会污染直方图**；
      3) 口径统一 `IRE = 0.2126R + 0.7152G + 0.0722B`（显示域），
         所以面板「平均亮度 × 100」**就是画面平均 IRE**，可跟色块直接对照校准。
    - 与「黑白预览」互斥：开一个会自动关掉另一个。
    - 状态：**已在编辑器里实测通过（2026-09-18）** —— 缩略图正常显示、档位"大体正确"
      （18% 中性灰落绿档）。实测首日曾因第四节那个崩溃级 bug 连续崩两次，已修。

    - 2026-09-18 **平滑去噪点（默认开，可关）**：
      - 分档前先按 N×N 求「块平均 IRE」再分档（N ≈ min(W,H)/160，夹在 2~16；1896×1321 时约 8×8）
        → 把逐像素跳档产生的彩色噪点抹平，得到**大块干净的色域**，更像监视器上那种一眼可读的伪彩。
      - 取舍：档位边界会糊几个像素；关掉开关即回到逐像素精确分档（真机语义）。
      - 依据：用户场景亮度分布是**双峰**（阴影 46.0% / 中间调 7.4% / 高光 46.7%），
        中间调极少 → 大量像素紧贴档位边界 → 逐像素分档必然出现彩色噪点（带纹理的表面最明显）。
    - 2026-09-18 **两种伪彩显示模式（一键切换，`OnCycleFalseColorMode`）**：
      - **连续色图（默认）**：整幅画面按亮度着色，**蓝=最暗 → 青 → 绿 → 黄 → 红=最亮**
        （黄→红之间线性插值自然经过橙；最亮端用红而不是白，高亮处一眼可辨）。
        实现是 256 项 **CLUT**（`FFalseColorProfile::Ramp`，5 个节点色线性插值），
        运行时每像素一次查表 —— 这就是用户要的"和相机伪彩一样"的效果。
      - **档位（曝光）**：只标关键档、其余显示灰度（真机监视器语义，用来判曝光对不对）。
      - 切换按钮在伪彩图上方那行左侧；图例文字随模式自动切换。
      - 顺带修文案：「粉=肤色」→ **「粉=浅肤色常见亮度（≈61–70 IRE）」**。
        RED 原文是 "Pink is typically the brightness of Caucasian skin tones" ——
        说的是**亮度位置**（不是颜色），且限定浅肤色（深肤色通常低 10~15 IRE）。

- **★ 链接坑：插件里引用 `GMaxRHIFeatureLevel` 会 LNK2019（2026-09-19 踩到）**
  - 该符号在 **RHI 模块**里，而 `HistogramAssistant.Build.cs` 的依赖是
    `Core/CoreUObject/Engine/Slate/SlateCore/UnrealEd/LevelEditor/DesktopPlatform/WorkspaceMenuStructure/RenderCore`

  - 更省事的修法（本次采用）：根本不传它。`GetUsedTextures(Out, QualityLevel, bAllQualityLevels,
    FeatureLevel, bAllFeatureLevels)` 在 `bAllFeatureLevels = true` 时**忽略 FeatureLevel 参数**
    （引擎只在 `!bAllFeatureLevels` 时才读它、也才用到 `GMaxRHIFeatureLevel`），
    所以传 `ERHIFeatureLevel::Num` 即可，不用加 RHI 依赖。
  - 另一种修法：Build.cs 里加 `"RHI"`。但如果只是想满足一个"用不到的参数"，不值得。
  - **⚠ 重要副作用：链接失败会连带把旧的 DLL 弄没**（`build27.log` 失败后
    `Binaries\Win64\UnrealEditor-HistogramAssistant.dll` 直接不存在了）。也就是说
    **编译失败必须立刻修好重编，别停在坏状态**——否则编辑器打开时插件加载失败、面板直接消失。

- **★ 链接坑：`UObject::GetResourceSizeBytes()` 不是 const 方法（2026-09-19）**
  - `GetReferencedTexturesAndOverrides` 给的是 `const UTexture*`，直接调 `->GetResourceSizeBytes(...)`
    编译不过 → 需要 `const_cast<UTexture*>`（或把容器改成非 const）。
- **★★ 崩溃级大坑：`UTexture2D::UpdateTextureRegions` 不拷贝 `Regions` 指针（2026-09-18 踩到，已修）**
  - 引擎实现（`Engine\Private\Texture2D.cpp:1402-1442`）：只做 `RegionData->Regions = Regions;`
    把指针存起来，**直到渲染线程才解引用**（`:1421` `RegionData->Regions[RegionIndex]`）。
  - 所以**绝不能在栈上构造 `FUpdateTextureRegion2D` 再传 `&Region`** —— 函数返回后那块内存失效，
    渲染线程读到垃圾区域/pitch，`RHIUpdateTexture2D` 建出非法拷贝 →
    **`Interfaces.CopyCommandList->Close() failed ... E_INVALIDARG`（D3D12Util.cpp:991）在 RHI 线程崩溃**。
  - 症状特征（差点误判）：**调用栈里没有任何插件帧**（命令是异步执行的，断言发生在渲染线程），
    所以只看栈会误以为与插件无关。
  - 正确写法：区域对象放堆上，在清理回调里和像素缓冲一起释放：
    ```cpp
    FUpdateTextureRegion2D* RegionPtr = new FUpdateTextureRegion2D(0, 0, 0, 0, (uint32)W, (uint32)H);
    uint8* SrcData = (uint8*)FMemory::Malloc(NumBytes);
    FMemory::Memcpy(SrcData, Pixels.GetData(), NumBytes);
    Texture->UpdateTextureRegions(0, 1, RegionPtr, W * 4, 4, SrcData,
        [RegionPtr](uint8* InData, const FUpdateTextureRegion2D*)
        {
            FMemory::Free(InData);
            delete RegionPtr;
        });
    ```
  - 附带确认：`UTexture2D::CreateTransient` 不设 `NeverStream`，但它没注册到流送管理器，
    `IsStreamable()` = `StreamingIndex != INDEX_NONE` = false（`StreamableRenderAsset.h:194`），
    所以 `UpdateTextureRegions` 不会走"静默跳过更新"那条分支。
  - 修复后重编：2026-09-18 10:41，`Total execution time: 6.88 seconds`，0 error / 0 warning。

  - `FViewport::ReadPixels` 填的 `FColor` **alpha 通道是 0**（编辑器视口的 alpha 没有意义；
    直方图只读 RGB，所以这个坑一直没暴露）。
  - 原先"非关键档"写的是 `FColor(Gray, Gray, Gray, C.A)` 和 `Dst[Index] = C` —— **沿用了 A=0** →

    只有关键档用 `Band.Color`（`FColor(r,g,b)` 默认 A=255）才是不透明的。
  - 症状：伪彩图看起来"只有边缘有零散色块、模型表面没被覆盖"，面板小图里则像"彩色散点"。

  - 修法：输出一律强制 `A=255`（灰度档 / 保留原色档 / 兜底分支 共三处）。

## 五、如何在 UE5 里使用
1. 打开 UE5 编辑器，进入 xiaozhen 工程
2. 菜单 `Tools（工具）→ 直方图助手（Histogram Assistant）`
   - 如果在 Tools 找不到，去 `Window（窗口）` 菜单找
3. 面板弹出后可拖到旁边停靠
4. 保持一个 3D 视口激活，点「捕获视口」或勾「自动刷新」
5. 顶部「显示」按钮：循环切换 综合 / RGB 独立 / 亮度 三种模式
6. 勾选「黑白预览」看明暗构图，取消勾选（或关闭面板）还原彩色
7. 勾选「伪彩色预览（曝光）」：面板里出现伪彩图（缩略图）——
   **绿=18% 中灰基准、粉=肤色、麦秆/黄=高光、橙/红=削波、紫/蓝=死黑、青=深阴影**，
   其余亮度显示灰度；「平均亮度 × 100」就是画面平均 IRE，可对照色块
   （与「黑白预览」互斥；开启时面板直方图会隐藏）
8. 两个可选开关（第二行）：
   - **「平滑去噪点（大块色域）」默认开**：分档前按块取平均亮度 → 没有彩色噪点、大块干净色域；
     关掉则是逐像素精确分档（会在纹理表面看到彩色噪点）
   - **「叠加到视口（大图）」默认关**：勾上把伪彩铺满整个 3D 视口。注意它是「抓下来的那一帧」，
     不跟随视角（建议配合「自动刷新」），切换视口后需要重新勾一次
   - 伪彩图**上方那行左侧**还有 **「伪彩：连续色图 / 档位（曝光）」按钮**，点击切换显示模式：

## 七、关键概念备忘

### 怎么读直方图
- 横轴 0~255：左=暗部(0-85)，中=中间调(86-170)，右=高光(171-255)
- 纵轴：该亮度像素的数量（越高越多）
- 山峰偏左 = 偏暗欠曝；山峰偏右 = 偏亮过曝
- 中间一大坨、两边空 = 发灰、对比不足
- 中间黄色竖线 = 平均亮度参考线（越靠右越亮）
- R 平均 ≈ G 平均 ≈ B 平均 = 不偏色；R 明显大于 B = 偏暖，反之偏冷

### 光照图 / 贴图尺寸 / 包围球半径 到底指什么（2026-09-19 记，回答用户提问）
- **「光照图分辨率」为什么是一个数而不是 128×128？**
  - 那个数是 `√(宽×高)`（面积开平方），**逐字照抄引擎** `PrimitiveStatsPage.cpp:216`：
    `LMSMResolution = TruncToInt32(Sqrt(LightMapHeight * LightMapWidth))`，再按组件数取平均。
  - 引擎为什么要开平方：光照图不一定是正方形（64×256 也是合法的），要压成一个数排序/比较，
    就用"等效正方形边长"= √面积。所以 128×128 → 128；64×256 → 也是 128。
  - **看到 12 就是 12×12 那种很小的光照图**（12×12=144=12²；也可能是 8×18 之类的组合）。
    这么小通常说明：模型很小 / 光照图分辨率设得低 / 光照图 UV 占比很小 / 根本没烘出像样的光照。
  - 插件现在**额外加了「光照图尺寸」列显示真实 W×H**，就是为了不用再去心算开平方。
- **「贴图分辨率」原来自带统计里没有**：`Primitive Stats` 是逐组件几何统计（三角面/材质槽/半径），
  贴图分辨率在另一个窗口 `Window → Statistics → Texture Stats`（而且它是"逐贴图"，不是"逐网格"）。
  插件补了「贴图最大」列 = 该网格材质用到的最大贴图 W×H，按网格视角看。
- **「包围球半径」**= `Component->Bounds.SphereRadius`，单位**厘米**：
  - 包围盒（AABB）外面套一个刚好裹住它的球，半径 = 球心到最远角的距离；
    比"最长边"更接近真实占据的空间（最长边 a → 半径 ≥ a/2）。
  - 用途：判断物体在场景里的**尺度**（人 ≈ 90 cm，小道具 ≈ 10~30，墙/地面几百到几千），
    以及 LOD / 距离剔除 / 流送距离的计算都基于它。
  - 看**最大**半径能一眼发现"这个实例被缩放放大了"（同一个网格的半径却差很多 = 缩放差异）。

### ⚠ 踩坑：查"材质用了哪些贴图"有两个坑，都必须避开（2026-09-19）
- **坑 1（材质来源）：不能用网格资产自带的材质槽。**
  - 错误写法：`Mesh->GetStaticMaterials()[i].MaterialInterface`。
  - 关卡/蓝图里经常把组件材质**覆盖**成另一套（`UPrimitiveComponent::OverrideMaterials`），
    这时资产自带那个材质可能引着完全不相干的贴图 → "明明是 1K 的模型，面板报 8K"（用户实测第二次）。
  - 正确写法：`Component->GetMaterial(SlotIndex)`
    （`UStaticMeshComponent::GetMaterial` 实现 = 先看覆盖，没有覆盖才落到 `StaticMesh->GetMaterial`）。
    - 注意 `UMeshComponent::GetMaterial` **不做回落**（没覆盖就返回 nullptr），
      只有 `UStaticMeshComponent` 重写版才会回落到网格材质 —— 我们拿的正是 UStaticMeshComponent，安全。
  - 结构上：材质引用要按**组件**收集（`FMeshUsageStat::Materials`），
    而不是在"每个唯一网格只算一次"的那段里算 —— 同一个网格的不同实例可能覆盖成不同材质。
    收集本身很便宜（只是取指针），真正贵的贴图解析仍然只对明细表 Top12 行做。
- **坑 2（贴图口径）：不能用 `GetReferencedTexturesAndOverrides()`。**
  - 它看名字像"实际用的"，其实是**并集**：材质图里引用到的**所有**贴图（含没走到的分支、材质函数里的）
    **∪** 参数覆盖。父材质"默认 8K、被材质实例覆盖成 1K"的情况会报 8K。
  - 正确写法：`UMaterialInterface::GetUsedTextures(Out, EMaterialQualityLevel::Num,
    /*bAllQualityLevels=*/true, ERHIFeatureLevel::Num, /*bAllFeatureLevels=*/true)`
    —— 走**编译后的 uniform 贴图表达式**，按材质实例求值
    （`UMaterialInstance::GetTextureExpressionValues`）= "这个材质真正会采样哪些贴图"。
    - `UMaterialInstance` 的实现会沿实例链找到第一个带静态参数的父级取资源；
      `bAllQualityLevels / bAllFeatureLevels = true` 时传入的 Quality / FeatureLevel 参数会被忽略（可传 Num）
    - 返回空 = 材质还没编译出资源 → 这时才退回并集版，并且**要在 UI 上标 ⚠**，别让用户以为算错了
- 排查思路：用户说"数字反了 / 串行了"时，先怀疑**口径**（"引用到的" ≠ "实际用的"、
  "资产的材质" ≠ "组件实际用的材质"），再怀疑行与数据的对应关系；
  最快的区分办法是**把中间产物（贴图名、来源材质、是否组件覆盖）显示出来**让人自查。
- 另一个同源坑：`UObject::GetResourceSizeBytes()` **不是 const 方法**，而
  `GetReferencedTexturesAndOverrides` 给的是 `const UTexture*` → 需要 `const_cast`（或换成非 const 容器）。

其余亮度：真机显示**去饱和灰度图**（不是满屏全彩）——本插件的「档位（曝光）」模式就是按这个做的。
出处：RED V-RAPTOR XL Operation Guide — False Color Video Mode。

### 8.2 校准流程（10 分钟，换相机/换工程/怀疑档位时跑一遍）

1. **先关自动曝光**（否则档位会随时间漂移）
2. 场景里放一块 **BaseColor = 0.18 的灰板**（用 Unlit 材质更干净）
3. 打开伪彩**档位模式**：**灰板必须显示绿色**
   - 显示蓝/青 → 数值被当成线性域了，需要做 OETF（`pow(1/2.2)`）
   - 显示黄/橙 → 阈值偏低，或场景曝光偏高
4. **交叉验证**：面板「平均亮度 × 100」≈ 画面平均 IRE（两者同源，天生该对得上）
5. 肤色材质应显示粉、过曝处应显示红

### 8.4 备选/已否决的实现路线（留档，避免重复踩）

- **后期材质版（路线 A）**：正规渲染路径，能在 PIE / 打包 / MRQ 生效；
  但要做材质 + 校准颜色空间，且当初就栽在「Custom 节点里手写 `SceneTextureLookup`」上。
  真要做：走「`SceneTexture` 节点 + Custom **命名输入引脚**」或「色谱贴图 + 纯节点」，
  并且**每次改完材质必查**日志里有没有 `Failed to compile Material`。
- **FSceneViewExtension + 自写 RDG pass（路线 C）**：最稳最正规（可在 Tonemap 前后精确插位置），
  但要写 usf + 处理模块加载阶段，工作量最大，当前需求用不上。
- **CPU 版（路线 B，已采用）**：零 shader 风险、可打印数字核对、天然不污染直方图；
  代价是只作用于编辑器视口、刷新率受 `ReadPixels` 限制（约 2Hz）。
